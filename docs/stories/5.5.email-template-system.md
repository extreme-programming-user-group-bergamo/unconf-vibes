# Story 5.5: Email Template System

**Status:** Done

**Epic:** 5 - Organizer Tools & Hotel Automation

**Issue Type:** Story

---

## Story

**As a** developer,  
**I want** a templated email system,  
**so that** automated hotel communications are structured and accurate.

---

## Acceptance Criteria

1. Email templates defined for: new booking, cancellation, modification
2. Templates include: guest name, room, dates, special requests
3. Template variables populated from booking data
4. Email rendering tested with MailHog in development
5. SMTP configuration via environment variables
6. SendGrid/Mailgun integration for production

### Architecture Alignment

- Preserve CLI as API client only; email business logic and rendering belong to backend service/email/repository boundaries.
- Keep handlers thin and push email composition/orchestration into service layer.
- Use provider abstraction so dev SMTP (MailHog) and production SendGrid/Mailgun can be swapped without CLI or handler coupling.
- [Source: docs/architecture/2-high-level-architecture.md#25-architectural-patterns]
- [Source: docs/architecture/6-components.md#62-component-responsibilities]
- [Source: docs/architecture/10-cli-backend-architecture.md#103-api-server-architecture]

### Data & Template Context

- Template variables should be derived from booking context: guest identity, room assignment, conference date window, and booking notes/special requests.
- Conference `hotel_email` is the expected destination anchor for downstream automation stories.

### Suggested Test Locations

### Key Test Scenarios

1. New booking template renders guest name, room, dates, and special requests correctly.
2. Cancellation template renders required placeholders correctly.
3. Modification template renders required placeholders correctly.
4. Missing optional special requests render safely without blank-template failures.
5. Booking data mapping populates all template variables from booking/conference/user context.
6. Development SMTP configuration sends rendered output to MailHog endpoint.
7. Provider mode selection chooses SMTP for dev and SendGrid/Mailgun adapters for production config.
8. Misconfigured SMTP/provider env values return deterministic, actionable errors.
