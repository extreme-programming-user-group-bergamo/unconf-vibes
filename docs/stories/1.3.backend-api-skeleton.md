### API Specification for This Story

### Structured Logging Configuration

[Source: architecture/16-coding-standards.md#critical-rules]

- **Framework:** Go 1.24+ `log/slog` standard library
- **Rule:** Use `log/slog` only; never use `fmt.Println` for logging
- **Pattern:** Initialize slog logger in main.go before starting server
- **Log Levels:** debug, info, warn, error
- **Example:**
  ```go
  import "log/slog"
  
  slog.Info("server starting", "port", port)
  slog.Error("failed to start server", "error", err)
  ```

### Error Handling Strategy

[Source: architecture/17-error-handling-strategy.md]

Error responses must follow this format:
```json
{
    "error": {
        "code": "health_check_failed",
        "message": "Health status unknown",
        "timestamp": "2026-02-14T10:30:00Z"
    }
}
```

Key rules:
- All HTTP responses are JSON
- Use consistent error codes (lowercase, snake_case)
- Include timestamp in error responses
- Return appropriate HTTP status codes (200 OK, 500 Internal Server Error, etc.)

### CORS Configuration for Development

[Source: architecture/14-security-and-performance.md#44-edge-and-abuse-controls]

- **Development:** Allow localhost:3000 (CLI dev server) and localhost:8080 (API)
- **Allowed Methods:** GET, POST, PUT, DELETE, OPTIONS
- **Allowed Headers:** Content-Type, Authorization
- **Exposed Headers:** Content-Type
- **Credentials:** Allow credentials in development only
- **Production Note:** CORS will be restricted to specific origins only; deny wildcard in production (implemented in later story)

### Graceful Shutdown Requirements

The API must handle graceful shutdown:
- Cancel in-flight requests with context timeout
- Close database connections cleanly
- Log shutdown events
- Exit with code 0 on success, 1 on error

**Implementation Pattern:**
```go
sigChan := make(chan os.Signal, 1)
signal.Notify(sigChan, syscall.SIGINT, syscall.SIGTERM)

go func() {
    <-sigChan
    ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
    defer cancel()
    router.Engine().Close() // or server.Shutdown(ctx)
}()
```

### Dockerfile Requirements

[Source: architecture/13-deployment-architecture.md]

The Dockerfile must:
1. Use Go 1.24+ official image as builder stage
2. Compile the server binary: `go build -o unconf-server ./cmd/server`
3. Use alpine:latest or scratch for runtime stage (minimal image)
4. Expose port 8080 (default API port)
5. Set entrypoint to `./unconf-server`
6. Include health check: `HEALTHCHECK CMD curl -f http://localhost:8080/health`

**Multi-stage build pattern (recommended):**
```dockerfile
FROM golang:1.24-alpine AS builder
WORKDIR /app
COPY . .
RUN go build -o unconf-server ./cmd/server

FROM alpine:latest
RUN apk add --no-cache curl
COPY --from=builder /app/unconf-server /
EXPOSE 8080
HEALTHCHECK CMD curl -f http://localhost:8080/health
ENTRYPOINT ["./unconf-server"]
```
