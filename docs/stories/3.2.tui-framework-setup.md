# Story 3.2: TUI Framework Setup

**Status:** Ready for Review

**Epic:** 3 - Room Exploration & Booking

**Issue Type:** Story

---

## Story

**As a** developer,  
**I want** Bubble Tea TUI framework integrated into the CLI,  
**so that** interactive terminal interfaces can be built.

---

## Acceptance Criteria

1. Bubble Tea dependency added and initialized
2. Lip Gloss integrated for styling
3. Base TUI model structure established (Model, Update, View pattern)
4. Common components created: header with context indicator, footer with help
5. Color scheme defined that works on limited-color terminals
6. Graceful fallback if terminal doesn't support TUI features

### Story Source

- **Reference:** [docs/prd/epic-3-room-exploration-booking.md](../prd/epic-3-room-exploration-booking.md)

### Previous Story Insights

- Story 3.1 established repository/service/handler wiring patterns and constructor-based dependency injection that should be preserved when adding TUI launch integration in CLI commands.
- Story 3.1 confirmed use of contextual error wrapping and structured logging patterns that should continue in TUI initialization/fallback paths.
- **Reference:** [docs/stories/3.1.room-data-model-api.md](3.1.room-data-model-api.md)

### TUI Architecture Guidance

- The architecture defines Bubble Tea model structure based on `Init`, `Update`, `View` methods and stateful model types.
- TUI interactions are launched from CLI command entrypoints and consume API-provided room data.
- **Reference:** [docs/architecture/10-cli-backend-architecture.md](../architecture/10-cli-backend-architecture.md), [docs/architecture/8-core-workflows.md](../architecture/8-core-workflows.md)

### File Locations

- CLI command integration point: `internal/cli/rooms.go`
- TUI model and rendering location: `internal/tui/rooms/`
- Shared styling and shell components: `internal/tui/common/styles.go`, `internal/tui/common/header.go`, `internal/tui/common/footer.go`
- **Reference:** [docs/architecture/source-tree.md](../architecture/source-tree.md)

### Technical Constraints

- Use Go 1.24+ and pinned terminal libraries (`bubbletea` v1.3+, `lipgloss` v1.1+).
- Terminal UX must remain compatible across macOS, Linux, and Windows terminals.
- TUI should preserve clear behavior on limited-color terminals.
- Maintain CLI-first behavior with graceful non-interactive fallback.
- **Reference:** [docs/architecture/tech-stack.md](../architecture/tech-stack.md), [docs/prd.md](../prd.md), [AGENTS.md](../../AGENTS.md)

### Coding Standards Constraints

- Wrap errors with context: `fmt.Errorf("context: %w", err)`
- Use `log/slog` for logging
- Pass context through I/O boundaries
- Prefer dependency injection and avoid global state
- **Reference:** [docs/architecture/16-coding-standards.md](../architecture/16-coding-standards.md)
