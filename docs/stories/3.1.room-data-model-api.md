## Story

**As a** developer,  
**I want** the room data model and API endpoints implemented,  
**so that** room information can be stored and retrieved.

---

## Acceptance Criteria

1. `rooms` table created with fields: id, conference_id, room_number, room_type (single/double/triple), price_per_night, capacity, created_at
2. `bookings` table created with fields: id, room_id, user_id, conference_id, status, notes, privacy_setting, created_at
3. Repository interfaces for rooms and bookings
4. `GET /conferences/{slug}/rooms` returns all rooms with availability
5. Room availability computed from bookings (spots taken vs capacity)
6. API returns occupant names only for Public bookings

### Database Schema

[Source: docs/architecture/9-database-schema.md]

**Migration 4 — `rooms` table:**

```sql
-- migrations/4_rooms.up.sql
CREATE TABLE rooms (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    conference_id INTEGER NOT NULL REFERENCES conferences(id) ON DELETE CASCADE,
    room_number TEXT NOT NULL,
    room_type TEXT NOT NULL CHECK (room_type IN ('single', 'double', 'triple')),
    price_per_night REAL NOT NULL,
    capacity INTEGER NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(conference_id, room_number)
);
CREATE INDEX idx_rooms_conference ON rooms(conference_id);
```

```sql
-- migrations/4_rooms.down.sql
DROP INDEX IF EXISTS idx_rooms_conference;
DROP TABLE IF EXISTS rooms;
```

**Migration 5 — `bookings` table:**

```sql
-- migrations/5_bookings.up.sql
CREATE TABLE bookings (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    room_id INTEGER NOT NULL REFERENCES rooms(id) ON DELETE RESTRICT,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE RESTRICT,
    conference_id INTEGER NOT NULL REFERENCES conferences(id) ON DELETE RESTRICT,
    status TEXT NOT NULL DEFAULT 'requested' CHECK (status IN ('requested', 'confirmed', 'cancelled')),
    privacy_setting TEXT NOT NULL DEFAULT 'public' CHECK (privacy_setting IN ('public', 'private')),
    notes TEXT,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    confirmed_at DATETIME,
    cancelled_at DATETIME
);
CREATE INDEX idx_bookings_room ON bookings(room_id);
CREATE INDEX idx_bookings_user ON bookings(user_id);
CREATE INDEX idx_bookings_conference ON bookings(conference_id);
CREATE UNIQUE INDEX idx_bookings_user_conference_active
    ON bookings(user_id, conference_id)
    WHERE status != 'cancelled';
```

```sql
-- migrations/5_bookings.down.sql
DROP INDEX IF EXISTS idx_bookings_user_conference_active;
DROP INDEX IF EXISTS idx_bookings_conference;
DROP INDEX IF EXISTS idx_bookings_user;
DROP INDEX IF EXISTS idx_bookings_room;
DROP TABLE IF EXISTS bookings;
```

The `migrations/embed.go` file uses `//go:embed *.sql` so new `.sql` files are included automatically.

### API Specification

[Source: docs/architecture/5-api-specification.md]

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | /conferences/:slug/rooms | No | List rooms with availability |

The endpoint is **public** — no authentication required. Register as an unprotected route (outside the auth middleware group).

**Response format for `GET /conferences/:slug/rooms`:**

```json
[
  {
    "id": 1,
    "conference_id": 1,
    "room_number": "101",
    "room_type": "double",
    "price_per_night": 85.00,
    "capacity": 2,
    "spots_taken": 1,
    "spots_available": 1,
    "occupants": [
      {"user_id": 5, "display_name": "Alice"}
    ]
  }
]
```

**Occupant visibility rules:**
- `privacy_setting == "public"`: include `user_id` and `display_name`
- `privacy_setting == "private"`: include only `display_name: "Private attendee"`, omit `user_id`

### `RoomResponse` and `OccupantResponse` Structs (Service Layer)

```go
type RoomResponse struct {
```

- `SpotsAvailable` = `Capacity - SpotsTaken`
- `Occupants` respects `privacy_setting` on each booking

### SQLite Repository Implementation Pattern

[Source: internal/repository/sqlite/conference_repository.go]

Follow the exact pattern used by `ConferenceRepository`:

- Constructor: `NewRoomRepository(db *sql.DB) *RoomRepository` / `NewBookingRepository(db *sql.DB) *BookingRepository`
- All methods accept `context.Context` as first param
- Use `db.QueryRowContext()` for single-row queries, `db.QueryContext()` for multi-row
- Check `sql.ErrNoRows` → return appropriate sentinel error
- Error wrap: `fmt.Errorf("failed to ...: %w", err)`
- Interface assertion: `var _ repository.RoomRepository = (*RoomRepository)(nil)`
- Use `slog.Debug()` on successful operations
