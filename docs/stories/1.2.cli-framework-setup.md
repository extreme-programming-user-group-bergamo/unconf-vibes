# Story 1.2: CLI Framework Setup

**Status:** Approved

**Epic:** 1 - Foundation & Authentication

---

## Story

**As a** developer,  
**I want** the Cobra CLI framework initialized with a root command,  
**so that** I can add subcommands for UNCONF features.

---

## Acceptance Criteria

1. Cobra initialized with `unconf` as root command
2. Viper integrated for configuration management
3. `--help` flag works and shows welcoming help text
4. `--version` flag displays version information
5. Configuration file support (`.unconf.yaml` or similar)
6. Basic error handling and exit codes established

---

## Dev Notes

### Technology Stack Reference

[Source: tech-stack.md#core-technologies]

This story uses the following framework versions:
- **Cobra:** v1.10+ (Command structure framework)
- **Viper:** v1.21+ (Configuration management)
- **Logging:** log/slog (Go 1.24+ stdlib, structured logging)

### Project Structure & File Locations

[Source: 11-unified-project-structure.md]

New CLI code must be created in these locations:


The CLI entry point in `cmd/unconf/main.go` should:

### Naming Conventions

[Source: coding-standards.md#naming-conventions]

- **Files:** snake_case (e.g., `root.go`, `booking_service.go`)
- **Packages:** lowercase, single word (e.g., `cli`, `service`)
- **Public functions/structs:** PascalCase (e.g., `NewRootCmd()`, `RootCmd`)
- **Private functions/methods:** camelCase (e.g., `handleVersion()`)
- **Variables:** camelCase (e.g., `versionFlag`, `configFile`)

### Configuration Management (Viper)

[Source: coding-standards.md#section-5-configuration]

Key principles for configuration:
- NEVER read environment variables directly (`os.Getenv`)
- Always use a Config wrapper that abstracts Viper
- Configuration should support:
  - Command-line flags (--flag-name)
  - Configuration file (.unconf.yaml)
  - Environment variables (UNCONF_FLAG_NAME format)
  - Sensible defaults

For this story, establish the config loading pattern. Future stories will expand the config structure.

### Logging Standards

[Source: coding-standards.md#section-4-logging]

- ONLY use `log/slog` for all logging output
- NEVER use `fmt.Println()`, `log.Printf()`, or other logging methods in production code
- Use structured logging with key-value pairs:
  ```go
  slog.Info("CLI started",
      "version", version,
      "config_file", configFile,
  )
  ```

### Dependencies & Error Handling

[Source: coding-standards.md#section-2-error-wrapping]

Error handling pattern:
- Always wrap errors with context using `fmt.Errorf("description: %w", err)`
- Never return raw errors without context
- CLI should exit with appropriate exit codes:
  - `0` = success
  - `1` = general error
  - `2` = usage error

## Tasks / Subtasks

### Task 1: Set up internal/cli package structure (AC: 1)
- [ ] Create `internal/cli/` directory
- [ ] Create `internal/cli/root.go` with root command function
  - [ ] Define `NewRootCmd()` function that returns a `*cobra.Command`
  - [ ] Set root command name to "unconf"
  - [ ] Set root command short description (welcoming message)
  - [ ] Set root command long description with usage information

### Task 2: Implement Cobra root command with help and flags (AC: 1, 3, 4)
- [ ] Import `"github.com/spf13/cobra"` in root.go
- [ ] Create `--version` flag that displays version information
  - [ ] Version should come from a package variable or config (e.g., `Version = "v1.0.0-alpha"`)
  - [ ] Flag should use `cobra.Command.Version` field
- [ ] Create `--help` flag (built-in to Cobra, verify it works)
  - [ ] Ensure help text is welcoming and guides users to next steps
  - [ ] Example: "UNCONF CLI — Unconference registration made easy"

### Task 3: Integrate Viper for configuration management (AC: 5, 6)
- [ ] Create `internal/config/` package with config wrapper
  - [ ] Do NOT call `os.Getenv()` directly anywhere
  - [ ] Create `Config` type with methods like `GetAPIEndpoint()`, `GetConfigFile()`, etc.
  - [ ] Implement `LoadConfig()` function that:
    - [ ] Reads from environment variables with `UNCONF_` prefix
    - [ ] Reads from `.unconf.yaml` config file (if exists)
    - [ ] Merges CLI flags with config file and env vars
    - [ ] Sets sensible defaults for required values
- [ ] Update root command to initialize config before running

### Task 4: Add configuration file support (AC: 5)
- [ ] Create sample `.unconf.yaml` configuration file in project root
  - [ ] Include example settings: `api_endpoint`, `log_level`, `config_file` path
  - [ ] Add comments explaining each setting
  - [ ] Document location: `.unconf.yaml` in project root
- [ ] Support config file specified via `--config` flag
- [ ] Support config file auto-discovery in home directory (e.g., `~/.unconf.yaml`)
- [ ] Viper should bind flags to config keys

### Task 5: Establish basic error handling and exit codes (AC: 6)
- [ ] Define error handling pattern for CLI
  - [ ] Create `internal/cli/errors.go` or similar
  - [ ] Define exit codes: `Success = 0`, `GeneralError = 1`, `UsageError = 2`
  - [ ] Implement error wrapping with `fmt.Errorf("description: %w", err)` in all functions
- [ ] Root command's `RunE` function should:
  - [ ] Return errors with proper context
  - [ ] CLI should use Cobra's error handling to exit with appropriate codes

### Task 6: Set up CLI entry point (AC: 1)
- [ ] Update `cmd/unconf/main.go` (created in Story 1.1) to:
  - [ ] Import `"github.com/unconf-vibes/unconf/internal/cli"`
  - [ ] Create root command using `cli.NewRootCmd()`
  - [ ] Execute the command: `rootCmd.Execute()`
  - [ ] Handle execution errors with proper exit codes

### Task 7: Add structured logging to CLI startup (AC: 1, 6)
- [ ] Import `"log/slog"` in root.go
- [ ] Add info-level log at startup showing:
  - [ ] CLI version
  - [ ] Config file location (if loaded)
  - [ ] Command being executed
- [ ] Example: `slog.Info("UNCONF CLI starting", "version", Version, "config_file", configPath)`

### Task 8: Unit tests for root command (Testing)
- [ ] Create `internal/cli/root_test.go`
  - [ ] Test case: `NewRootCmd()` returns non-nil command
  - [ ] Test case: `--help` flag works and outputs help text
  - [ ] Test case: `--version` flag outputs version string
  - [ ] Test case: Invalid flags produce usage error (exit code 2)
  - [ ] Use Go testing stdlib (`testing.T`)
  - [ ] Use `testify/assert` for assertions (included in tech-stack.md)

### Task 9: Integration test for config loading (Testing)
- [ ] Create `internal/config/config_test.go`
  - [ ] Test case: Config loads from `.unconf.yaml` file
  - [ ] Test case: Config loads from environment variables (UNCONF_ prefix)

## Testing

### Test File Locations & Patterns

[Source: coding-standards.md#naming-conventions]

- Unit tests: `{package}/{file}_test.go` (e.g., `internal/cli/root_test.go`)
- Integration tests: Same location with `*_integration_test.go` suffix (if needed)
- Use Go's `testing.T` for all tests
- Use `testify/assert` for assertions

### Testing Pyramid & Strategy

[Source: 15-testing-strategy.md#151-testing-pyramid]

- **60% Unit Tests:** Root command setup, flag parsing, config loading
- **30% Integration Tests:** Config file loading + Viper integration (use temporary test files)
- **10% E2E:** Manual testing of actual CLI execution
