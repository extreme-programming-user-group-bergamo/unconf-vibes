# Story 1.1: Project Scaffolding

**Status:** Approved

**Epic:** 1 - Foundation & Authentication

---

## Story

**As a** developer,  
**I want** the project repository initialized with Go module, folder structure, and basic tooling,  
**so that** I have a clean foundation to build upon.

---

## Acceptance Criteria

1. Go module initialized (`go.mod`) with appropriate module path
2. Standard Go project layout created (`/cmd`, `/internal`, `/pkg`)
3. `.gitignore` configured for Go projects
4. `README.md` with project overview and setup instructions
5. Makefile or task runner with common commands (`build`, `test`, `lint`)
6. `golangci-lint` configuration file present

---

## Dev Notes

### Technology Stack Reference

[Source: architecture/tech-stack.md#core-technologies]

- **Language:** Go 1.24+ (primary requirement for all application code)
- **Versions:**
  - Go: 1.24+ (newer performance and tooling baseline per architecture decision)
  - SQLite: 3.40+ (already decided; includes JSON functions, window functions)
  - golangci-lint: v2.x (pin latest stable)

### Project Structure & File Locations

[Source: architecture/11-unified-project-structure.md]

The repository structure MUST follow this layout:

```
unconf/
├── .github/
│   └── workflows/
│       ├── ci.yaml              # Test, lint on PR
│       ├── release.yaml         # GoReleaser on tag
│       └── deploy.yaml          # Deploy to Fly.io
├── cmd/
│   ├── unconf/                  # CLI binary entry point
│   │   └── main.go
│   └── server/                  # API server binary entry point
│       └── main.go
├── internal/
│   ├── api/                     # HTTP API (Gin handlers)
│   ├── cli/                     # CLI commands (Cobra)
│   ├── tui/                     # TUI components (Bubble Tea)
│   ├── service/                 # Business logic layer
│   ├── repository/              # Data access layer
│   │   ├── interfaces.go
│   │   └── sqlite/
│   ├── models/                  # Domain models/structs
│   ├── auth/                    # Authentication logic
│   ├── email/                   # Email service
│   ├── config/                  # Configuration management
│   └── client/                  # HTTP client for CLI
├── migrations/                  # Database migrations (golang-migrate format)
├── configs/                     # Configuration files (.yaml, .env examples)
├── scripts/                     # Build/deploy scripts
├── docs/                        # Documentation
├── Dockerfile
├── docker-compose.yml
├── fly.toml
├── Makefile
├── .goreleaser.yaml
├── .golangci.yaml
├── go.mod
├── go.sum
└── README.md
```

### Coding Standards

[Source: architecture/coding-standards.md#naming-conventions]

- **Files:** snake_case (e.g., `booking_service.go`, `booking_test.go`)
- **Packages:** lowercase, single word (e.g., `service`, `repository`, `api`)
- **Go modules naming convention:** Use descriptive package names following Go conventions

### Testing Strategy

[Source: architecture/15-testing-strategy.md]

- **Go 1.24+** includes built-in testing via `go test`
- **Test pyramid:** 60% unit, 30% integration, 10% E2E
- **Testing dependencies:** stretchr/testify v1.11+ for assertions (will be added to go.mod in later story)

### Required Go Module Path

No specific guidance in architecture docs. Standard Go convention: Use GitHub repository path as module name.  
Suggested: `github.com/katurdays/unconf` (based on workspace path structure)

### Task 3: Configure `.gitignore` for Go (AC: 3)

Create `.gitignore` file with Go-specific patterns.

**Subtasks:**
1. Create `.gitignore` at repository root
2. Add Go-specific patterns:
   - `*.o`, `*.a`, `*.so`
   - `*.test`
   - `*.out`
   - `/bin/`
   - `/dist/`
   - `.DS_Store` (macOS)
   - `.env`, `.env.local`

   - `config.local.yaml` (local overrides)
   - `debug` executables
3. Commit `.gitignore`

**Testing:** Verify with `git check-ignore -v *.db go.test` returns matches

### Task 4: Create `README.md` with Project Overview (AC: 4)

Create comprehensive README with setup instructions for developers.

**Subtasks:**
1. Create `README.md` at repository root
2. Include sections:
   - **Project Overview:** Brief description of UNCONF CLI project
   - **Quick Start:** Installation and basic usage (`unconf login`, `unconf help`)
   - **Development Setup:** Prerequisites (Go 1.24+, SQLite 3.40+, Make, golangci-lint)
   - **Building:** `make build` instructions
   - **Testing:** `make test` instructions
   - **Linting:** `make lint` instructions
   - **Project Structure:** Reference to `docs/architecture/11-unified-project-structure.md`
   - **Documentation:** Links to `docs/architecture/`, `docs/prd/`
   - **Contributing:** Link to coding standards at `docs/architecture/coding-standards.md`
3. Reference tech stack versions from [Source: architecture/tech-stack.md]

**Testing:** Verify README is readable and all links are valid: `grep -E "^\[|^#" README.md`

---

### Task 5: Create Makefile with Build Commands (AC: 5)

Create `Makefile` with essential development tasks.

**Subtasks:**
1. Create `Makefile` at repository root
2. Define targets:
   - `make build` — Compile CLI and API binaries to `/bin/unconf` and `/bin/unconf-server`
   - `make test` — Run `go test ./...` with `-race` flag
   - `make lint` — Run `golangci-lint run ./...`
   - `make run-cli` — Build and run CLI binary
   - `make run-server` — Build and run API server binary
   - `make clean` — Remove `/bin/` and test artifacts
3. Add `.PHONY` declarations for all targets
4. Include phony targets for future: `migrate-up`, `migrate-down`, `docker-build`

**Testing:** Verify targets exist: `make -n build lint test` shows commands without executing

---

### Task 6: Create `golangci-lint` Configuration (AC: 6)

Create `.golangci.yaml` configuration file for linting standards.

**Subtasks:**
1. Create `.golangci.yaml` at repository root
2. Configure linters:
   - Enable: `gofmt`, `goimports`, `vet`, `ineffassign`, `errcheck`, `unused`, `staticcheck`, `gosimple`
   - Disable: `revive` (too many false positives)
3. Set timeout to `5m`
4. Exclude patterns for test files (if needed)
5. Set output format to `colored-line-number`

**Testing:** Verify with `golangci-lint version && golangci-lint run --no-config ./... --debug` returns linter info

---

### Task 7: Verify All Files Created & Commit

Verify all acceptance criteria files are in place and commit foundation.

**Subtasks:**
1. Verify files exist:
   - `go.mod` ✓
   - Directory structure per AC2 ✓
   - `.gitignore` ✓
   - `README.md` ✓
   - `Makefile` ✓
   - `.golangci.yaml` ✓
2. Run `make lint` — Should pass (or have only suppressed issues)
3. Run `go mod tidy` to clean up `go.mod` if needed
4. Commit all files with message: "Story 1.1: Project Scaffolding Foundation"

**Testing:** Final verification:
