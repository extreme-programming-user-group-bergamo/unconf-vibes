# Story 5.9: Status Command Lifecycle Consistency

**Status:** Done

**Epic:** 5 - Organizer Tools & Hotel Automation

**Issue Type:** Story

---

## Story

**As an** attendee,  
**I want** `unconf status` to consistently reflect my live booking lifecycle state,  
**so that** I can trust booking visibility immediately after cancellation and related workflow updates.

---

## Acceptance Criteria

1. `unconf status` returns current active-conference booking details when an active booking exists.
2. After a successful `unconf cancel` flow, `unconf status` shows a clear no-active-booking outcome in the same conference context.
3. Cancelled bookings are excluded from active status projections and occupancy-facing status output.
4. Status rendering remains privacy-aware for roommate visibility and retains existing roommate-preservation behavior.
5. Status and cancellation error paths continue to use normalized API error mapping and clear CLI feedback.
6. Automated regression coverage includes an explicit cancel→status command-path assertion validating post-cancel state consistency.
